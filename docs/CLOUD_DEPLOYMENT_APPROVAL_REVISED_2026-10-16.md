Cloud Run Job `parallelism=1` limits tasks **within** an execution, not concurrent executions. Atomic Supabase claims prevent duplicate jobs for one project. Per-user/daily beta quotas remain; broad traffic needs an execution concurrency cap or queue. Production scene and render routes fail closed until their Job names are configured. API scenes use a PostgreSQL atomic lease; worker verifies owner and token, and token-guarded database writes prevent an expired worker from overwriting a newer claim. The 25-minute scene lease outlasts its 20-minute Job timeout. Expired scene status recovery and release are atomic. Render claim also clears an expired scene lease and uses token-guarded writes; a stale render state is recovered after 45 minutes. If Cloud Run accepts a Job but its API response is lost, the claim stays active until the worker completes or the lease expires, avoiding a second submission. Noncritical analytics failures cannot reverse a dispatched Job. A restart alone cannot lose a running Job or create a second claim. **Only live Cloud Run tests can prove this under real terminations and network failures.**
