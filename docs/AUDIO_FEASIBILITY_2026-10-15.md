# Indian-language audio feasibility checkpoint — 15 October 2026

**Result: partial integration with a real Telugu CPU sample.** The app routes explicitly to a Piper service when the operator records a model revision, hardware requirement and commercial-license assessment. A local evaluation service produced three Telugu samples through the adapter. The same provisional three-case corpus and evidence report now cover all 11 app languages. Real open-model samples for the other ten, native-speaker quality review and deployed app generation remain outstanding, so no cross-provider winner can be named. Telugu, Hindi, Tamil and Marathi are the first acceptance group; the other seven follow the same evaluation stages. See the [real-sample report](../test_reports/PIPER_TELUGU_REAL_2026-10-15.md) and [coverage matrix](AUDIO_LANGUAGE_COVERAGE.md).

## Current application proof

- `backend/piper_tts.py` is an HTTP adapter, not an inference server. It checks the operator's voice manifest and calls only `/synthesize` on that server.
- `backend/ai.py` routes by explicit provider and does not automatically fall back. Premium speech requires request-level selection and matching operator configuration.
- `backend/projects.py` includes provider/model revision in scene-audio cache identity and records Piper model ID and synthesis milliseconds on generated scenes.
- `backend/audio_eval_corpus.py` defines the same three provisional case types for all 11 creation languages. `backend/benchmark_piper_audio.py` accepts each language but writes actual MP3s and a report only when a reviewed voice and service exist; Piper's catalog alone does not cover Tamil and Marathi. `backend/audio_coverage.py` reports which languages have complete local sample evidence. Cost fields remain unset until real billing data is available.
- Regression evidence: the prior full backend baseline was 238 tests plus six subtests. An earlier Piper-focused run passed 11 backend tests; the latest 11-language corpus and premium-gate focus passed 11. The current frontend suite passed 14 tests, build and compile passed. A separate real Telugu run produced 3.47, 10.32 and 5.96-second decodable MP3s with 3.300, 1.288 and 0.779-second wall times. Neither the tests nor the signal check prove linguistic quality.

## Feasibility blockers and next gate

The laptop had about 2.59 GB free at initial inspection. A roughly 64 MB Telugu weight was downloaded for the bounded local run. The existing Google Cloud project is `ayana-video-studio`, but read-only billing inspection failed because the saved Cloud SDK token needs interactive reauthentication. A prior L4 VM request was rejected under the free-trial billing account, per `deploy/indic-voice-eval/README.md`. Current GPU eligibility, CPU limits, remaining credit and cost are unknown. No cloud service, VM or paid inference was created in this work.

The next acceptance work is fluent-speaker review of the 11 provisional scripts and Telugu audio, then a commercially suitable model and bounded inference route covering all 11. Record service RAM, concurrency, attribution, distribution obligations, pronunciation, consistency and realistic infrastructure cost per language. Test the full app project through render/download in all four primary languages and then the other seven. Compare against Chirp only after an explicit cost cap is approved. Until then, preserve the working Edge/Chirp routes and do not start image or video open-model integration.
