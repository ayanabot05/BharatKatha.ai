# VidBharat independent audit — 13 October 2026

## Verdict

Not ready to claim category leadership or finished fine-tuning. Reliability improved, but realistic action, generated motion, native-language editorial quality and complete live story evaluation remain open. No cloud training execution has started. This is an evidence checkpoint, not a release approval.

## Completed and verified

- Backend regression suite: **113 passed, six subtests**, with five deprecation warnings. Includes adversarial script checks, current-review fingerprints, caption validation and concept evidence validation.
- Frontend regression suite: **5 passed**. Tests spoken opening/ending edits, stopping overlapping voice previews, ignoring late preview responses, unavailable Odia voices and a single inline scene-approval error without a duplicate toast.
- Frontend production build passed after the feature changes.
- Real speech matrix: **20 short samples across ten languages** decode and produce valid caption timings. All **11 offered languages** render captions. Latest cached rerender passed after explicit bundled Latin-font selection; font logs contain no Arial fallback or unresolved-glyph error.
- Bengali zero-length initial word boundary is handled by grouping with the next measured word rather than discarding it.
- AI narration uses provider word timestamps where available. Estimated timing is labelled. Uploaded speech with captions enabled must successfully transcribe; script text is no longer silently substituted for the recording.
- Review fingerprints prevent changed story inputs from reusing an old passing review. Concept approvals require citations to scene text and the original idea. This verifies evidence provenance, not semantic completeness.
- Voice previews stop when another preview starts or the tab changes. Hook/ending edits update the actual spoken scene narration. Odia AI voice is explicitly unavailable.

## Output failures and gaps

1. **Physical action still fails.** The fresh image and its refinement preserve the dry setting and characters, but the refined pipe scene still shows disconnected geometry and an implausible repair. Neither image is approved as a correct repair demonstration. See `repair_scene.png`, `repair_scene_refined.png` and their prompts.
2. **True animation is absent.** Current video rendering moves the camera over still pictures. It does not generate body motion, interacting objects or lip sync.
3. **Text-provider availability:** the saved minimal text probe failed with quota; the separate image worker succeeded. A text outage must not be reported as proof that images are unavailable. The new concept-evidence schema has regression coverage but has not passed a live provider test.
4. **Language scope:** eleven caption languages, ten speech languages, no Odia AI voice. Short sample rendering and audio decoding do not establish pronunciation, idiom, fluency, cultural fit or long-video quality. No native-speaker approval is recorded.
5. **Timing:** saved Golden Harvest remains 34.97 seconds against a 30-second target; the UI now exposes measured audio mismatch, but exact target-duration generation is not solved.
6. **Coverage:** no claim of testing every input, every language worldwide or every competitor. UI regression tests are not a complete browser accessibility or mobile audit. Both UI-automation runtimes currently fail initialization with a missing kernel-assets path.

## Training: exact status

User requires Google Cloud execution. **No local training has run.** `backend/training/cloud_train.py` refuses to fit outside Cloud Run; its refusal was verified. Preparation and syntax checks do not constitute training.

The prepared experiment trains a character-based language classifier and adapts its weights to short excerpts. It selects the checkpoint on validation data and evaluates the chosen checkpoint against held-out source test data. It uses the publicly sourced WiLI-2018 archive, with checksum, attribution and ODbL provenance. It uses no OpenAI internal training data. It does not fine-tune a generative story/image/video model.

Proposed Cloud Run envelope: one CPU, 4 GiB RAM, one task, 20-minute timeout, zero retries. Cloud Build builds the container; Cloud Storage stores data, weights and evaluation. Local fitting and local Docker builds are unnecessary. Job outputs must be reviewed before application integration; the prepared code does not automatically approve itself for production.

**Submission is pending authenticated gcloud access.** The user is enabling it. The private bucket, service account, project permissions and available services still require inspection. No trained weights or measured model gains are claimed.

## Competitive bar

Official competitor capabilities establish a higher bar than a technically valid MP4: Runway supports reference-driven imagery and generated moving video; HeyGen provides multilingual video-translation workflows. VidBharat needs demonstrated regional storytelling fidelity, intelligible natural speech, correct physical action, consistent characters, useful creator control and predictable time/cost to justify switching. No controlled head-to-head customer evaluation has established that advantage.
